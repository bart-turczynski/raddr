# Working method

Demoted verbatim from `AGENTS.md` on 2026-09-05. Self-references such as "this file" and "this section" refer to the original.

Five rules that were carried in per-session agent memory rather than in the repo, promoted here on 2026-09-05 when that store was retired (`RADD-fspbtslz`). The evidence behind each one is in `docs/` and is cited inline; what was missing was the rule.

- **Survey peers by running them, not by citing a survey.** Where a name, a vocabulary level or an API shape is in question, execute the comparable implementations and report what each one *does*, not what its docs claim. This changes the argument at least as often as it confirms it: `unallocated` was settled against three tools that each assert something false about IETF-reserved IPv6 space, two of them calling it `is_reserved` while simultaneously reporting `is_global == True` (§5.3.2), and the shape of the provenance fields was settled by the one surveyed library that carries provenance at all (§5.3.6). `docs/research/06-library-divergence.md` and `09-peer-parser-conformance.md` are executed comparisons rather than reading notes — keep them that way, and re-run rather than re-cite.

- **Grade an RFC's normative force from the RFC text, never from a paraphrase.** Before anything hard-codes what a standard *requires* — a `strength` grade, a "MUST drop" claim, a conformance code — fetch the document and check two separate things: whether it invokes RFC 2119 anywhere, and what the governing sentence actually says. Those come apart in both directions, which is the whole reason to check both: RFC 4291 and RFC 8215 invoke 2119 nowhere and still state definitional rules, while RFC 4193 invokes it and states §3.1's rule in lowercase (§5.2.3, `R/codes.R`). Errata count and have a status worth quoting — `errata.rfc-editor.org/eidNNNN`, and Errata 1752 on RFC 5180 §8 is why P9 takes that value from the registry. An fp issue description or a `docs/research/` note is a paraphrase for this purpose, however carefully it was written.

- **Agreement between the two implementations is the null result.** §11.3 gets its value from `tests/testthat/helper-slow.R` being independently right, not from it agreeing: both sides restate §3 from the same author's reading, so they can share a misreading of the spec and agree forever, and a green suite cannot see that. In a manual verification pass, write the expected answers down from the specification or the vendored CSV *before* opening either implementation, and re-derive a claim from the raw source rather than through the package's own accessor, which is circular. Ask what each side thinks it is doing and whether that is what the spec says — not whether they match. The corollary for a change that moves no answers is already worked twice in §11.2.4: assert agreement, then build the wrong version on purpose and confirm the corpus can disagree.

- **An upstream bug report is done when it is committed, not when it is filed.** Four conditions, none needing network: reproduced against the live library at a named version and platform; the claim narrowed to what the measurement supports, with no RFC 2119 language the spec does not license; duplicate-checked against the upstream tracker; and submission-ready in `docs/upstream-reports/`. Filing measures an account raddr does not control, and defining done that way left five issues sitting at `todo` with nothing left to do on them. All five reports and the epic over them are closed (`RADD-dtdcaphz`, 2026-08-12); unfiled is the intended end state rather than a residual task, and publication, if it ever happens, is a new issue. The one carve-out is the CRAN submission — no local artifact substitutes for a published package, so that one stays open.

- **Open the development version in the same session as a release.** Tag the release, then bump `DESCRIPTION` to `<version>.9000` and add an empty `# raddr <version>.9000` heading to `NEWS.md`. Two commits with the tag between them, and it is part of cutting the release rather than something to ask about: if `HEAD` keeps the release number, later work is silently filed against a released version and the next `NEWS.md` entry lands under the wrong heading.
